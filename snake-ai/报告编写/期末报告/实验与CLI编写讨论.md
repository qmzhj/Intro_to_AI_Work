# 报告编写讨论记录

## 一、第 4 节子节结构安排

训练过程描述.md 的内容按迭代时间线展开，建议拆分为多个子节放入第 4 节：

```
4.1 实验软硬件环境
4.2 实验任务与评价指标体系
4.3 对照实验方案
4.4 训练过程与迭代优化
  4.4.1 初始训练瓶颈与参数优化
  4.4.2 CNN 模型轻量化改造
  4.4.3 探索率衰减 Bug 修复
  4.4.4 奖励函数多轮调优
  4.4.5 CNN 空间分辨率修复
  4.4.6 Double DQN / Dueling DQN / PPO 扩展训练
  4.4.7 后期优化与最终训练结果
4.5 实验结果汇总
4.6 实验结果深度分析
4.7 实验现存问题与溯源分析
```

理由：训练过程描述.md 记录的是"发现问题→分析原因→修改参数→验证效果"的完整迭代链条，属于实验开展过程的范畴，放在实验结果汇总之前可为后续数据展示提供上下文。

## 二、AI CLI 工具使用说明的位置

讨论方案：

### 方案 A（推荐）：放在 4.1.2 软件环境中

原始骨架的 4.1.2 标题为"软件开发与仿真环境（含 CLI 辅助开发说明）"，AI CLI 作为开发工具，放在环境说明中顺理成章。

拟写内容示例：

> "项目研发过程中，使用了 AI CLI 工具（Claude Code）辅助代码编写、Bug 排查与实验日志分析。例如训练过程中出现的探索率双重衰减 Bug、奖励函数参数调优方向、超参数取值建议等，均通过与 AI CLI 的交互分析实验日志后确定。"

同时在 4.4 各子节的具体迭代描述中自然带出（如"通过 AI CLI 分析日志发现探索率衰减异常"）。

### 方案 B：放在 3.5 模型训练与优化策略

问题：3.5 讲的是算法层面的技术策略（学习率、梯度裁剪、训练流程），加入 AI CLI 使用说明会打断技术叙述的连贯性。

如果要放，只适合在 3.5.1 末尾加一句简短说明，不宜展开。

### 结论

采用方案 A，AI CLI 的说明放在 4.1.2 软件环境部分，4.4 各子节在具体迭代描述中自然带出。
